⚠ 注意点

地図上には順番番号を表示しません。管理IDは編集画面だけで識別するためのもので、走行順ではありません。
新規追加用の入力欄です。既存ポイントを直す場合は、下の一覧から「内容編集」を押してください。
新規追加：内容を入力→「新規注意点を追加」→地図を動かす→「この位置に決定」。既存修正：一覧の「内容編集」または「位置変更」を使います。

📍 チェックポイント

C1・C2…だけが走行順です。番号は作成順ではなく、現在のルート上の位置順で自動表示します。
通常時にC1/C2…を触っても位置は変わりません。既存CPを動かすときだけ、一覧の「位置変更」を押してください。

📝 ルート概要

「どのチェックポイントから、どのチェックポイントへ」の説明文を、このルートJSONの中に保存します。分岐・EXTRAも任意の組み合わせで登録できます。
保存キーは「出発CP名→到着CP名」です。QUEST本体も同じキーを読む設計に統一します。

🚻 トイレ

地図上は🚻アイコンだけを表示します。管理IDは編集用で、走行順を意味しません。
新規追加用の入力欄です。既存トイレを直す場合は、下の一覧から「内容編集」を押してください。
新規追加：施設名を入力→「新規トイレを追加」→地図を動かす→「この位置に決定」。既存修正は一覧から選びます。

⛺ 大会・合宿 拠点

テント・本部・集合場所などの固定拠点です。人の現在地とは別データとして保持します。指導者・コーチ・保護者が現地でGPS登録できる構造です。

🅿 駐車場出入口

車両の駐車位置は登録しません。必要なのは会場へ出入りするための駐車場出入口だけです。入口・出口・共用を固定ポイントとして表示します。

👥 ROLE / 表示色

人の位置マーカーは役割ごとに区別します。初期設定では指導者を専用色にしています。色・略号・表示ON/OFFはここだけで変更できます。

📱 参加者は本体で自由登録

参加者をエディタへ事前登録しません。 大会・合宿の本体公開後に、選手・保護者・指導者・コーチが自分のスマホから登録します。
全員が入力
名前 ／ 役割（選手・指導者・コーチ・保護者）
選手だけ入力
競技種目 ／ 競技時間
投稿された参加者・競技予定は本体側の DATA ADAPTER に保存します。エディタのMAP設定とは別データなので、ルートや会場MAPを更新して本体を再生成しても参加者投稿を作り直さない設計です。

⏱ 競技予定も本体投稿

選手本人が参加登録時に競技種目・競技時間を入力します。エディタで選手別予定を作成する必要はありません。
将来、複数種目登録や招集時間を追加する場合も RUNTIME REGISTRATION MODULE の更新だけで拡張します。

🧩 SYSTEM BUILD

このエディタを設計元（SOURCE OF TRUTH）にします。MAP・拠点・駐車場出入口・ROLEをMAP BLOCKから本体へ渡します。参加者・競技予定は本体公開後の自由投稿データとして別管理します。
会場設定はエディタ → MAP BLOCK → 本体生成の一方向です。参加者投稿は本体 DATA ADAPTER 側に残すため、MAPを更新して本体を再生成しても参加者を再登録しない設計です。将来Firebaseを導入するときはDATA ADAPTERだけ差し替えます。

保存

v20はMAPをブロック単位で保存し、同じデータから見守りシステム本体を自動生成します。大会・合宿見守り用の拠点・ROLE・駐車場出入口を設定し、参加者・競技予定は生成後の本体で自由投稿します。旧v15/v13/v12/v10のJSON・端末保存も読み込み可能です。STAGE型では同じPROJECT ID / ROUTE IDでSTAGE IDを変えて保存、STAGEなし型ではCHECKPOINT ROUTE、MAP ONLY型ではルート線だけを再利用できます。モードを切り替えても既存CP・注意点データは削除せず保持します。変更のたびに直前状態を最大5世代まで自動バックアップします。
